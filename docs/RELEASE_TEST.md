# 배포본 검증 순서

## 검증 절차

1. 게임 종료 확인 후 현재 패치 파일·설정·캐시·생성 interop를 별도 백업한다. 새 설치본에는 옛 플러그인을 겹쳐 놓지 않는다.
2. 격리된 설치 대상에서 Install → 파일 해시 대조 → 재설치(변경 0) → Restore → 원래 바이트 대조를 수행한다. 손상 payload, 수동 수정 파일, 다른 플러그인이 있을 때 쓰기 전에 중단하는지도 확인한다. 복구 재실행과 설치 중단 후 receipt 복구를 확인한다.
3. 실제 순정 게임 폴더에 이번 ZIP을 설치한다. 첫 실행의 interop 생성, 이후 재시작을 확인한다. 설정 `Dictionary`를 비워 동봉 경로가 사용되는지 로그와 실제 엔진 로드를 확인한다. 기존 외부 hdTrans 경로가 성공의 원인이 되지 않게 검증한다.
4. Unity 6000.3.5f2/IL2CPP 시작, 긴 스토리 타이핑 종료, 본문·화자 폰트, 첫 대사, 제어 태그, 늦은 응답 폐기, 스킵·즉시 표시·페이지 전환을 확인한다.
5. 아티팩트 전환/장비 선택, 파견 시간 갱신, 시련의 제단 기간/안내 반복 표시, 프리즌 타워 보상, 랭킹 수량, 소환 보석/서로 다른 티켓 확인창을 확인한다. 긴 스킬·좁은 버튼과 숫자·Rich Text 보존도 확인한다.
6. 새 캐시 생성 후 게임을 재시작해 재사용과 즉시 표시를 확인한다. 진단 빌드를 쓴 경우 최종적으로 진단 없는 패키지 DLL로 돌리고 해당 해시를 다시 대조한다.
7. 실제 설치 복구 및 재설치를 확인하고 정상 설정으로 마무리한다. 소환·보상 수령·전투·장비 변경 등 계정 재화/진행 상태를 바꾸는 동작은 실행하지 않는다.

## 통과 후 공개

실제 시험 결과와 남은 제한을 기록하고 설치 ZIP·대응 소스 ZIP·SHA256SUMS를 같은 GitHub Release에 게시한다.
공개 저장소의 코드와 ZIP에 들어간 소스가 일치해야 한다. 임시 로그·캐시·게임 자산·개인 경로는 게시하지 않는다.
설치 ZIP 안에도 대응 소스를 유지한다.
